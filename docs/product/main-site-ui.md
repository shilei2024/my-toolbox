# 主站界面规范

## 目标与边界

主站首页是面向已登录和访客的工具工作台：用户应直接进入工具分类与工具入口，不使用营销型 Hero 取代核心工作内容。客户项目跟进属于业务能力，因此其入口与 FCST、报销、发票等卡片同处“业务工具”分类，而不是独立平行分类。

本次改动仅调整表现层和首页信息架构：不变更客户项目的权限、功能开关、路由、数据模型、审计记录或 API。

## 主题策略

主题使用 `html[data-theme]` 上的全局设计令牌，覆盖主站公共导航、首页工具库、客户项目工作台及通用 Bootstrap 表面；业务模块保留自身的语义色彩。设置只保存在当前浏览器的 `localStorage`，无需登录、数据库字段或额外部署配置。

| 标识 | 名称 | 适用场景 |
| --- | --- | --- |
| `obsidian` | 曜石专业（默认） | 高对比、沉稳的长期工作台使用 |
| `github` | GitHub 风格 | 克制、清晰的协作与工具浏览 |
| `bright` | 明亮风格 | 光线充足环境下的轻快阅读 |

## 设计与维护约束

- 新的全站颜色、阴影、边框和圆角应优先使用 `static/css/style.css` 中的主题令牌，避免把某个主题的固定颜色写入组件。
- 新主题属于可复用的平台展示能力，不与 AI、支付、存储或客户项目业务逻辑耦合。
- 主题偏好缺失或浏览器拒绝本地存储时，必须安全回退到默认曜石专业主题。
- 曜石专业必须覆盖 Bootstrap 表单、下拉、只读/禁用控件、表格、弹窗、警告、分页与关闭按钮，以及报销和客户项目模块的语义表面；模块不得用固定浅色背景叠加继承的浅色文字。
- 主题切换必须保留键盘焦点、可读文本与足够的前景/背景对比度；动画须尊重系统的减少动态效果设置。

## Golden Rule 结论

1. 会影响生产网站：是，仅限客户端视觉呈现，随静态资源版本发布。
2. 可被未来 AI 模块复用：是，主题令牌和偏好机制位于主站公共壳层。
3. 更低成本方案：是，CSS 变量与浏览器本地偏好不需要服务端状态、迁移或运维资源。
4. 新手可部署和维护：是，无新增环境变量、数据迁移或发布步骤。
5. 符合长期架构：是，表现层独立于领域模块、提供方与平台核心服务。

## 回滚

回滚只需恢复主站模板、`static/css/style.css` 和 `static/js/main.js` 的对应版本；不涉及数据库、缓存、消息队列或外部服务，浏览器中残留的主题偏好会自动回退到默认主题。
