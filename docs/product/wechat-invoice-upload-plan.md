## Golden Rule

1. 生产会受新增移动入口影响：默认关闭，迁移只加表和附件摘要列，开启前验证；不改变既有票据金额。
2. 可复用：外部身份映射、一次性绑定挑战、撤销式移动会话与账户审计放 auth 域；上传幂等与票据保存留在报销域。
3. 最低成本方案：原生小程序 + 现有 Flask/PostgreSQL，复用附件/用量；无需云开发、消息队列或独立服务。
4. 新手部署：环境变量开关、原生开发者工具导入、独立恢复库演练和逐步发布手册；AppSecret 不进入聊天或代码。
5. 符合长期架构：同一网站用户、权限、业务服务和管理后台；不直接信任 openid/owner_id，不另建账户或业务数据库。

## 范围与契约

- 网站登录用户经密码再次验证，生成 10 分钟、192 位随机一次性绑定码；新码使旧码失效。小程序 code 经服务端微信换身份后才能消费绑定码。公开接口不接收可信 openid。
- 外部身份是 provider + app_id + subject 的唯一映射；解绑保留审计并立即吊销全部会话。重绑不得静默覆盖有效映射，旧会话绑定原用户，不能随身份转移到新账号。
- 移动 Bearer 256 位随机令牌只存摘要，7 天有效，重新 wx.login 可登录已绑定身份；停用用户、解绑、撤销、AppID 不符均拒绝。移动接口只接受 Bearer，不接受网站 Cookie；不颁发网站 Cookie，不使手机令牌可登录其他模块。
- 网站绑定接口仍用登录态与 CSRF，只有 Bearer-only 移动蓝图豁免 CSRF。敏感响应 no-store；微信响应错误脱敏，session_key 不保存不返回。
- 单张原件与票据、幂等凭证、用量在同一事务落库；客户端重试同一幂等键和相同意图返回同一票据，变更内容返回 409。用户行锁与唯一约束防并发重试，内容摘要避免原件重复。
- 普通票据默认 review，其他用途默认 retain。手机不填金额、不自动冲减公里、不调用 OCR；只拍照/选图/PDF、周期/用途/发生月、进度/重试、列表和原件。桌面继续核对金额、ZIP、分摊、导出和打印。
- 不自动认领匿名历史票据。绑定同一网站账号的数据才共享；匿名迁移须另行明确来源和确认，禁止以手机号、openid 或客户端 owner_id 认领。
