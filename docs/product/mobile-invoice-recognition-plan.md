# 手机票据识别、核对与完整录入

2026-10-29。用户已确认真机绑定、上传、网站同步成功，明确要求继续实现识别后完整录入；此为0.9.48之后的新增能力，不能把上传当成录入完成。

## Golden Rule / 实施方案

1. 会影响主站OCR共享代码及手机入口；保留桌面接口，复用现有金额/归属/汇总规则，OCR只给草稿，确认前不改变财务记录。
2. 复用模块内按字节OCR服务、已有账号/工具授权/附件/票据保存与审计；不另建后台、OCR供应商或权限系统。
3. 现有同步OCR链+按票据原件缓存最省成本，无队列/云服务；PG非阻塞事务咨询锁防同票并发OCR重复付费，客户端顺序识别并可重试。
4. 无迁移/新依赖，仍按现有PR/恢复库验收/最终备份/发布和手动服务器命令；保留本机开发工具未提交配置。
5. 符合模块化单体：OCR属于报销模块，手机走受控Bearer API，确认共用网站保存逻辑，不把业务提升为新平台服务。

范围：上传后自动识别，在手机显示现有网站录入项（号码、日期、商家、未税金额、税额、价税合计、摘要、周期、办事处、费用类别、产品线、用途、发生/结算月、打印、计入口径、备注），支持编辑及明确确认保存；已有上传记录亦可进入核对。OCR失败或缺字段须人工补齐，不伪称完整识别。网站尚无独立发票代码/购方税号等列，不把供应商额外字段偷偷作为新财务字段；未来扩展需独立数据设计。

接口：本人票据详情+版本快照、识别草稿、确认提交；新增refs供类别/产品线选择。识别结果保存现有领域审计作为草稿缓存，不自动覆盖票据；确认检查owner/工具授权/会话、快照、日期/金额及合计、归属目录，拒绝已分摊账单修改。普通票只有用户明确选择计入费用才计入；加油/过路/账单维持retain规则。确认后网站、Excel/汇总使用同一记录；沿用网站关联明细规则并保留已有手填明细，专属应酬/出差字段仍在网站补齐，不改公里数。

主要文件：共享OCR提取工具模块、auth移动路由/领域函数、新原生核对页、客户端顺序识别与状态、相关API/ADR/部署文档、金额/权限/并发/缓存/失败/真实客户端回归。无DB迁移。回滚可退0.9.48兼容f5，已确认字段保留，审计草稿仅新客户端使用；不能回滚到忽略retain的旧版。

验收：真实图片/PDF识别、草稿不影响汇总、人工确认入库完整字段、同文件重试复用草稿/票据、旧页面不能覆盖新修改、跨用户/撤销权限/已分摊账单拒绝；已有OCR降级回归与网站金额/导出回归必须通过。生产真实OCR与真机需操作者最终验证，不用mock代替真实供应商效果。

底部改为四个原生tab：首页/发票录入/派车单/我的。首页负责当期选择与同口径仪表盘；当期在进程内共享并以本人周期清单校验，发票和派车单页不再重复选择。我的负责登录/扫码绑定/状态/退出，退出清空共享周期且上传中不允许退出，派车未保存须明确放弃。保留原有隐私授权。
