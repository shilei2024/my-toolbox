# 发票小程序界面精简（2026-11-12）

## 目标与范围

减少解释性文字和重复入口，让用户优先看到当前周期、上传、核对与保存。仅调整原生小程序五个页面及共享样式；沿用客户权限修复分支，不改网站、接口、数据库或计费规则。

## 设计评估与实施计划

- 生产影响：网站服务与数据契约不变；小程序需独立预览、体验版验收后发布。
- 复用：字号、卡片、按钮与可展开说明为共享样式；票据计费说明保留在发票模块。
- 成本：使用原生 WXML/WXSS 和现有状态，不引入组件库、服务或付费资源。
- 维护：只涉及五个页面和三个局部展开状态，沿用开发者工具上传流程。
- 架构：鉴权、金额确认、隐私授权、客户隔离和提交接口继续使用现有实现。
- 工作量：一轮界面调整及针对性回归；无需迁移或服务器发布。

## 页面变化

| 页面 | 设计 |
| --- | --- |
| 工作台 | 直接显示功能名称；周期之后提供快捷录入；合并重复刷新入口 |
| 发票 | 拍照/相册与 PDF 两个入口；计费规则按需展开；本次上传与本期发票分区 |
| 核对 | 保留票面、金额、归属、客户与发生月；金额规则及结算/打印设置展开查看；折叠时显示当前打印状态 |
| 派车单 | 直接命名；编辑完成和整单保存明确区分；有改动时提示未保存 |
| 我的 | 默认账号密码登录；微信、扫码和绑定码集中到展开区域 |

视觉统一为 40rpx 页标题、30rpx 分区标题、28rpx 输入正文、26rpx 标签；卡片间距 20rpx、内边距 28rpx。展开按钮保留 88rpx 点击高度。保留隐私授权原文、金额核对开关和保存确认。

## 体验版验收与回退

1. 在微信开发者工具打开 `apps/invoice-miniprogram`，编译五个页面；确认无模板或样式错误。
2. 在窄屏和常见手机上检查长客户名、长文件名、大金额、键盘遮挡及底部安全区。
3. 验证上传、失败重试、金额说明展开、客户新增/选择、发生月、结算/打印展开和确认保存；收起设置再展开，值应保留。
4. 验证密码、扫码、绑定码和已绑定微信登录；登录入口展开不应清空已填信息。
5. 派车编辑完成后须显示未保存提示，整单保存成功后消失；从网站核对保存结果。
6. 体验版确认后通过微信后台发布。异常时恢复上一个小程序版本；本次不需要数据库恢复或服务器回滚。
