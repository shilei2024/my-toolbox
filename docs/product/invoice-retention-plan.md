# 发票留存与手机录入实施计划

状态：网站端本地实现及回归完成，待评审、PostgreSQL 演练与预发布；小程序待开发；2026-10-28。从 origin/main f086b4f 开始，未经上线验收不代表已交付生产。

## Golden Rule 与范围

1. 生产影响：会改变报销统计与打印行为；历史默认计入，新增字段兼容迁移，先预发布验证。
2. 复用：继续使用平台身份、所属人隔离、附件和限流；分摊属于报销领域，不提升为通用 AI 服务。
3. 成本：现有 Flask/PostgreSQL + 浏览器 ZIP 最低成本，无新队列、微服务或云资源。
4. 新手维护：提供迁移、备份、验证和回滚命令；小程序凭据单独配置，不影响网站使用。
5. 长期架构：共享账号与存储，不另建后台；小程序只提供录入入口。

## 实施顺序与工作量

网站闭环：模型与兼容迁移、manager API/汇总/导出、两个模板、领域计算、回归测试（中等）。
手机入口：先核对微信官方契约，再实现绑定/身份/上传与客户端（较大），需要小程序主体、AppID、合法域名及开发者工具验收。
生产：独立评审、测试、预发布、可恢复备份后通过 PR 发布；不直接修改 main 或生产数据。

## 网站验收

- 用途：普通发票、零散过路费、加油票、通行账单。新增后三种默认仅留存打印；普通发票默认计入。
- 计入口径：计入费用、仅留存打印、待确认。后两种不进入任何费用统计/封面/关联明细。
- 打印状态独立；阈值筛选只影响打印。未知金额不自动作为零处理，应提示待确认；5 元保留。
- 开票日、发生月、结算月、归属报销周期分开；账单不按开票日自动归属。
- 分摊按自然月选派车行，整数分保证合计，预览与手动调整后确认保存，记录来源和变更。
- 加油票不冲减实际公里数；抵扣公式尚未提供，仅作核对凭证。
- ZIP 原件不自动上传服务器：保留本地源文件并主动导出/归档，不能把浏览器内存称为持久保存。

## 风险与验证

重点检查历史口径、不同产品线重复计入、跨用户/周期、边界金额、OCR 失败、重复文件、分摊并发及导出一致性。
本地 SQLite 回归不能替代 PostgreSQL 备份恢复库迁移演练。迁移新增列而不重写历史金额。
旧程序忽略新计入口径，因此开始使用留存票据后不得直接回滚旧程序恢复费用导出：先停用入口与导出，优先前滚修复，或恢复发布前备份到隔离库核对。
