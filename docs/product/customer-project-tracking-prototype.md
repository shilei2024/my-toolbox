# 客户项目跟进低保真原型（Phase 0）

> 本原型用于冻结信息层级与关键交互，不代表最终视觉稿。界面优先简体中文，并在 320px 以上浏览器可用。

## 全局信息架构

登录后模块导航为：`我的工作台`、`客户`、`项目`、`量产汇总`、`失败复盘`、`报表`。组织管理员在现有统一后台额外看到成员与权限、字段字典、提醒策略、通知日志和回收站；不创建独立后台。

## 新建项目向导

步骤固定为“客户与项目 → 成员 → 物料 → 下一步”。允许保存草稿；正式提交前必须有客户、名称、阶段、主业务、下一步和跟进时间。物料允许 0 条竞品，型号未知时明确勾选“型号待确认”。

## 新增跟进（移动端首要动作）

表单按顺序显示跟进类型、发生时间、摘要、客户反馈、风险/决策、下一步、下次跟进时间和参与人。提交成功才显示保存时间和操作者；网络失败保留输入且不得显示“已保存”。

## 冲突处理

当服务器返回 409 时，用对话框并列显示“你的输入”和“服务器最新内容”，提供“复制我的内容”“刷新为最新版本”和“返回手动合并”。没有“强制覆盖”快捷按钮。新增活动为追加操作，不允许编辑覆盖历史正文；纠错通过更正事件留痕。

## 生命周期确认

量产、失败、暂停、归档、重新激活和衍生使用确认向导，先展示影响，再要求条件字段和原因。操作只改变同一项目状态或创建带来源的新项目，不把数据移动到另一张业务表。

## 可访问性验收

- 键盘可完成搜索、筛选、新建、跟进和保存；焦点顺序与视觉顺序一致。
- 表单错误紧邻字段并有文字说明；状态和逾期同时使用图标/文字。
- 触控目标至少 44×44 CSS 像素；320px 宽度无水平滚动（数据表改卡片）。
- 页面存在唯一主标题、结构化表头、跳转主内容入口和可读的按钮名称。
