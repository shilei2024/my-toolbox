# 手机高铁票缺少金额拆分修复

2026-10-31。用户反馈只识别出票价、未识别未税金额与税额时，手机确认出现“未税金额加税额必须等于价税合计”，无法完成录入。这是确认校验错误，并非登录凭据失效。现有网站旧记录导入采用未税金额缺失则合计减税额的记录约定；移动端此前将空白强制当0，产生差异。

## Golden Rule 与实施计划

1. 影响生产手机识别/确认及核对页，独立 hotfix PR、恢复库、独立审查、最终备份后人工部署；无数据库迁移。
2. 复用报销领域纯金额函数及既有确认/审计/快照/导出；金额拆分属报销边界，不增加平台认证或AI服务。
3. 只用Decimal补缺失字段，无税率推断、额外OCR请求、队列或云资源，运行成本不增加。
4. 沿用Flask/systemd和固定SHA人工发布；旧客户端空白提交也兼容，可独立回滚代码保留f5与新记录。
5. PostgreSQL继续为事实源；缺失字段处理不绕过明确确认、owner权限、用量或乐观锁，符合现有单体架构。

范围：retention纯函数、mobile_recognition草稿与旧缓存及确认、原生review页、相关API/PG/JS与恢复库验收、上线文档。既有金额完整但不一致仍拒绝；负数/NaN/越界仍拒绝；明确0不视作空白。合计与税额已知可相减，未税金额与合计已知可相减，未税与税额已知可相加。仅合计已知时提供“金额=票价，税额暂记0”的人工核对建议，提示不代表免税或可抵扣，不按高铁类别猜税率。已有税额不得覆盖为0。

草稿不改变费用；旧缓存读取时补齐，不重新调用收费OCR；确认时同样处理旧客户端空白并记录amount_note。新版显示提示及“按票价补齐金额”显式按钮；填写部分金额时不再把空白当0覆盖票价。按钮允许用户按合计减当前税额覆盖未税金额，清除确认状态，要求再次核对。

风险：只有合计并不证明税额为0，故明确提示核对，后续可按原票编辑；不做税务抵扣判断。不更新历史票据或强行改写已填数值。回归涵盖总额单独识别/旧缓存/老客户端/部分缺失/真零与不一致/非法金额、网站/Excel、owner与会话。预计小范围修复与发布验证，服务短维护时停写备份。
