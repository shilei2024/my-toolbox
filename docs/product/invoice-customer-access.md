# 发票助手普通账号新增客户

日期：2026-11-11。状态：本地回归通过，候选待CI及发布验证。

## 问题与验收

网站与小程序当前用客户项目模块开关、试点名单及组织销售角色判断新增客户权限。仅有发票助手授权、没有组织成员身份的普通账号无法新增客户。

已登录、有效且获发票助手授权的账号均可新增本人客户；网站和小程序返回相同目录与等级。仍具备客户项目创建权限的账号沿用原组织客户创建路径，其余账号使用个人客户空间。普通账号不会因此获得组织成员身份或客户项目权限。未授权、禁用、匿名及跨账号访问必须被拒绝。

## Golden Rule 与实现计划

- 生产影响：更改两端 bootstrap/create API 和客户解析，需权限、历史数据及跨端回归后发布。
- 复用：继续用 customers 作为唯一客户事实源，复用创建校验和审计；个人客户空间属于客户领域，不另建报销客户表。
- 成本：复用 organizations 作为个人数据容器；首次有效创建时按账号稳定 UUID 创建一行，不创建 membership，不新增数据库结构、依赖或基础设施。
- 部署：后端兼容现有 customer_creation_enabled 字段；后端发布后刷新网站/小程序即可显示入口。回滚只退代码并保留数据，旧代码暂不显示个人客户。
- 架构：组织客户和组织角色保持原行为，个人目录与组织内本人/历史共享目录取并集；个人空间不会因加入组织而丢失。禁止在 GET 请求创建空间。

改动范围：客户创建服务与个人空间服务、报销 manager、mobile routes、权限/跨端回归测试、API/ADR/变更记录。以一个功能分支完成；数据库及 API 字段无破坏性变更。验证普通账号无组织、FAE/只读成员、管理员、开关关闭、双端创建/上传/回显/Excel、越权和旧组织记录。提交前检查全部相关测试及差异。
