# 小程序派车编辑与票据核对精简

## 目标与实施边界

同一周期按日期稳定排序，仅首行填写起始公里，后续行只读并承接上行终止公里。新增、改日期时重新判断首行资格；改变首行位置时保留原周期起始读数。点击“完成编辑”直接调用现有 PUT 接口，删除确认后也直接保存。失败保留编辑器、已保存列表和快照，允许重试或刷新，不展示外部“保存派车单”按钮。

发生月份非必填，但月度通行账单对账及分摊依赖它。移除独立卡片，放入默认收起的“更多信息”，与可选结算月、打印设置一起展示；不删除字段、不清空历史月份、不自动推测月份。

## 设计门禁与风险

- 生产影响：仅更新小程序客户端；网站服务、权限、数据库及 API 契约不变。仍由服务端执行里程串联、分摊保护及快照冲突校验。
- 复用与架构：派车公里链和票据月份属于报销模块；继续复用平台登录与请求能力，不新增模块专属基础设施。
- 成本：原生页面调整，无新依赖、服务及运行成本；直接上传小程序即可维护。
- 范围：修改 dispatch 页面 JS/WXML、review 页面 WXML、客户端回归测试与文档，工作量为一次小型客户端修复；无迁移。
- 风险：回填较早日期改变行顺序；网络失败可能已在服务端完成提交。继续保留旧快照，冲突时提示刷新核对，不自动覆盖或重复创建。

## 验证与发布

### 同组按钮并排布局

派车列表的“新增派车记录 / 刷新”集中在列表上方同一行，编辑器“完成编辑 / 取消”也并排。同步整理首页两项快捷录入、新增客户“保存并选中 / 取消”、两处隐私弹窗以及微信登录/连接网站账号入口；已有原件操作、编辑/删除、图片/PDF 上传沿用统一样式。不同步骤或作用域的操作不强行合并。

复用全局 button-row / upload-actions，等分宽度、拉伸等高、文字居中、间距 16rpx、行顶部间距 24rpx，清除原生按钮自身外边距，避免一行中高低不齐。保留禁用、加载、隐私授权属性及所有事件绑定。纯 WXML/WXSS 调整，可复用到模块内后续页面，无新依赖、数据库、API、服务器影响和运行成本，沿用原有架构；回退上一客户端即可。人工验收检查窄屏与大字体下的换行、加载图标、弹窗和点击反馈。

自动回归覆盖首行必填、后续只读、日期重排、直接保存、重复点击、失败重试、删除保存及月份保留。另运行派车 API、发票核对和原生客户端现有测试。

本地验证：` .venv/Scripts/python.exe -m unittest tests.test_mobile_miniprogram_client tests.test_mobile_dispatch tests.test_mobile_form_parity tests.test_mobile_password_login` 共 27 项通过；Node 语法、两页 WXML 标签结构与 `git diff --check` 通过。尚未执行微信开发者工具编译和真机验收。

发布前用体验版验证：首行 100、实际 10，次行自动起始 110；修改首行实际公里后下行重新计算；回填日期仍只有首行可编辑起始公里；完成编辑即同步网站；无发生月份的普通票据可保存，已有月份保持。自动化不能替代真机验证。

使用微信开发者工具导入 `apps/invoice-miniprogram`，上传递增版本并设置体验版，通过以上检查后提交审核，审核通过再发布。服务器不需要更新或重启。失败时保留当前正式版；发布后异常可按微信后台可用能力回退上一正式版本，已保存数据不随客户端回退删除。
