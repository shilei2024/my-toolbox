# Phase 3–6 实施与发布计划

用户于 2026-11-14 授权持续开发至可上线，并要求人工部署命令。

## 设计门禁

- 生产影响：涉及所有登录和找回；以加法迁移、功能默认关闭、先迁移后启用和真实恢复验收控制。
- 复用：认证邮件、一次性令牌、绑定与安全设置均为平台能力；注册自动授予发票权限仅属于小程序业务入口。
- 成本：复用现有 SMTP、Flask、PostgreSQL；邮件任务由现有部署环境定时运行，不新增 SaaS。
- 维护：一个配置入口、可重试任务、脱敏检查、明确升级/回退命令；不要求人工修改用户数据。
- 架构：保持 users.id 和全部业务归属，不自动合并两份有数据账号。

## 工作与验收顺序

1. Phase 3：通用 SMTP 传输、认证邮件任务/令牌、验证邮箱/找回密码、账号安全页；令牌仅存摘要，异步邮件不落原始链接，重置原子消费并撤销全端。
2. Phase 4：兼容无邮箱/密码账号、新微信注册同事务创建身份和 reimbursement grant、移动端账号信息与操作入口。开关默认关闭，唯一冲突整事务回滚。
3. Phase 5：绑定来源会话校验、双端确认、禁止冲突账号自动合并、最后身份保护；下游身份撤销检查。
4. Phase 6：单元/接口/迁移/并发/前端验证、补运维检查和发布文档。真实 SMTP、微信后台、生产恢复数据、域名/TLS等只能在用户环境验收，不将模拟测试称为上线验收。

涉及 auth/shared/models/config/templates、mini lib/页面、Gallery/Generation认证、migrations、tests、scripts/ops 与集中 docs。预计多模块工作，测试按阶段执行。历史 UI/Phase 1/2 未提交内容保留，不重置工作树。

## HTTPS邮件表单修复（2026-11-16）

生产反馈找回提交400。代码核验：account_security响应no-referrer及邮件落地页meta no-referrer会让浏览器HTTPS POST不带Referer，与Flask-WTF默认SSL严格同源校验冲突。改为same-origin，令牌继续放fragment、不进入来源URL；跨站不发送来源，同站来源用于严格校验。影响全平台账号邮件入口，可复用既有CSRF和浏览器策略，无新依赖/成本/数据库迁移；只更新代码并重启即可，保持认证架构。新增开启CSRF+HTTPS的真实模板提交测试和恶意来源/缺token拒绝测试，修复后推进hotfix合并。回退代码应继续保留CSRF，不能通过关闭保护解决。
