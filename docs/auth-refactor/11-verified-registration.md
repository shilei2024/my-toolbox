# 邮箱验证后完成注册

2026-11-16，用户授权实施网站注册验证、注册成功邮件与找回密码闭环。

## 设计门禁与范围

- 生产影响：改变网站新注册，增加一个加法迁移；旧用户、权限、密码、归属及微信注册规则保持兼容。先升级结构再更新代码；恢复库/PG16演练后才部署。
- 平台复用：注册申请、邮件任务和一次性凭据属于通用认证。沿用同一SMTP传输与专用发件身份，不增加供应商或服务。
- 简化与成本：独立待验证申请记录，完成验证前不创建users或签发业务会话；现有邮件队列增加可空注册申请引用。没有额外Redis/进程，仍使用现有定时器。
- 新手维护：提供收信等待页、限流重发、过期后重新申请、完成页及登录/找回引导；所有原始令牌仅在发信内存和邮件中。
- 架构：AccountRegistration持有邮箱和待验证token摘要，设置密码并验证后同事务创建现有User与身份、标记完成并入队欢迎邮件。不自动关联同邮箱的既有账号，不更改历史用户验证状态。邮箱所有者在邮件链接内设置密码，避免预注册者保留一个自己已知的密码。

## 文件、数据库与API

涉及auth/account_models、registration_service、email_service、routes/forms、注册/等待/邮件落地/找回/全站验证提示模板、迁移、运维工具、tests及集中docs。新增account_registrations，邮件任务user_id变为可空并增加registration_id与互斥CHECK，兼容已有任务。GET注册链接只展示，POST携带CSRF、token、新密码完成注册；无原始token落库。注册与重发使用IP和邮箱摘要限流、每地址一分钟冷却。欢迎邮件只入队一次，可按原任务重试。

## 风险与验证

账号争用、并发重复激活、重复邮件/网络失败、邮箱枚举、预注册劫持、邮件不可用、CSRF/同源策略、开放重定向和旧客户端兼容均须测试。重点验证HTTPS真实模板：申请→收信→验证设置密码→欢迎邮件→登录→找回→改密→旧会话失效；未验证不产生User或会话，过期重发不覆盖现有账号。

SQLite功能回归、PG16并发/迁移和全部既有认证/微信/业务回归按风险执行；生产需备份及恢复库验收。预计多模块工作，分实现、回归、发布文档三步完成。

## 部署与回退

新结构为加法且旧邮件任务兼容；新增注册任务启用后，旧代码无法派发这类任务，因此不得自动回退旧dispatcher。停止邮件定时器和网站更新后再启动。失败优先前进修复；不要删除待验证申请或清空队列，不回滚已成功注册的用户。欢迎邮件投递失败不撤销已完成的注册。具体命令在实现与演练通过后补充。
