# 发票提取与批量打印工作台

## 目标与边界

主站只展示一个“发票提取与批量打印”工具，统一接收 ZIP、PDF 和图片。PDF/图片保留在
浏览器内存；只有 ZIP 为执行递归解压而短暂上传到 Flask 服务，并且只在请求内存中处理，
不写磁盘、不进入对象存储或数据库。

## 处理流程

1. 浏览器将不超过安全门限的 ZIP 按批发送到 `/tools/invoice-printer/analyze`。腾讯云主站
   默认允许单个 ZIP 20MB、单批 ZIP 合计 20MB，并始终在 Flask 全局上传门限下预留
   1MB multipart 开销；不再沿用旧 Vercel 4MB 限制。
2. 服务端沿用 `tools.zip_extractor` 的深度、单条目、累计解压体积和压缩比限制，提取并
   按内容哈希去重 PDF。
3. 浏览器把返回的 PDF 转为本地 `File`，与直接选择的 PDF/图片加入同一工作台。
4. 预览、删除、单份打印、批量合并打印及 ZIP 导出均在浏览器完成，不产生持久文件。

待处理清单和结果清单使用统一事件委托：可以逐项删除、清空待处理、删除勾选项或清空
全部结果。处理中会锁定清单，失败或被服务端跳过的 ZIP 会保留在待处理区，避免用户误以为
处理成功。相同名称和大小但内容不同的压缩包提取结果按内容哈希区分。

可选环境变量为 `INVOICE_ZIP_MAX_MB`、`INVOICE_ZIP_BATCH_MB` 和
`INVOICE_ZIP_RESPONSE_MB`（默认分别为 20、20、48）。调整前必须同时核对
`MAX_UPLOAD_MB`、Gunicorn/Nginx 请求体限制及服务器内存；单包和单批值会自动受
`MAX_UPLOAD_MB - 1MB` 约束。

历史 `/tools/zip-extractor` 页面和分析接口由通用 `route_aliases` 机制映射到同一蓝图，
不会产生第二张首页卡片或第二套业务逻辑。所有新旧入口统一使用 `invoice_printer` 用量口径。

## 生产、复用、成本与运维结论

- 生产影响：首页入口不变；修复上传门限和清单交互，发布无需停机或数据迁移。
- 复用：路由别名是工具注册层能力，后续工具更名/合并可复用；解压安全核心保持单一实现。
- 成本：PDF/图片、合并和导出仍在客户端完成，服务器只承担原有 ZIP 解压请求。
- 新手部署：普通代码发布即可，无新增依赖、数据库迁移或云资源；新增环境变量均为可选，
  使用默认值无需修改腾讯云配置。
- 长期架构：工具 UI 负责工作流编排，安全解压能力保持独立模块边界，没有把文件持久化
  或发票业务耦合进共享认证、存储等平台服务。

## 验证与回滚

发布后分别访问新旧网址，确认均显示统一工作台；上传一个 4–20MB、包含嵌套 ZIP 的样例
以及直接 PDF/图片，确认逐项删除、清空待处理、删除勾选、清空全部、继续追加、批量打印
和导出。再上传超限 ZIP，确认页面明确提示且文件仍保留在待处理清单。若需回滚本次修复，
恢复上一版本代码并重启服务即可；没有数据库或持久文件需要回退。
