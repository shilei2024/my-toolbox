# 发票提取与批量打印工作台

## 目标与边界

主站只展示一个“发票提取与批量打印”工具，统一接收 ZIP、PDF 和图片。PDF/图片保留在
浏览器内存；ZIP 也在浏览器内递归解压，不再上传到 Flask、Cloudflare 或其他网站入口，
不写磁盘、不进入对象存储或数据库。这是工具级本地文件能力，不属于共享 AI 任务服务。

## 处理流程

1. 浏览器按最多两个顶层 ZIP 并发调用 JSZip，避免页面因大量任务同时占用内存。单包仍限制
   20MB；无需经过 Cloudflare、Caddy、Gunicorn 或 Flask，因此不受 HTTP 524 和响应体
   Base64 膨胀影响。JSZip 3.10.1 及其 MIT/GPL 许可证随主站静态资源发布，优先本地加载；
   两个固定版本 CDN 只作为静态资源异常时的降级来源。
2. 浏览器端沿用服务端相同的安全边界：最深 8 层、单成员解压后 32MB、每个顶层 ZIP
   累计 64MB、压缩比不超过 100。扩展名为 `.zip`、`.zipx`、`.pdf` 的成员直接处理；只对
   无扩展名成员检查文件签名，XML、OFD、图片等辅助文件直接跳过。
3. 提取出的 PDF 直接创建本地 `File`，使用 SHA-256 内容摘要去重，与直接选择的 PDF/图片
   加入同一工作台。浏览器不支持 Web Crypto 时使用包含文件长度的本地后备摘要。
4. 预览、删除、单份打印、批量合并打印及 ZIP 导出均在浏览器完成，不产生持久文件。

待处理清单和结果清单使用统一事件委托：可以逐项删除、清空待处理、删除勾选项或清空
全部结果。处理中会锁定清单，未找到 PDF、损坏、加密或触发安全门限的 ZIP 会保留在待处理
区，并在固定错误面板和对应文件下显示具体原因。由于提取过程不发起 HTTP 请求，不再存在
批次重试、入口超时、重复服务器任务或 HTTP 524 错误。
相同名称和大小但内容不同的压缩包提取结果按内容哈希区分。

页面只保留文件选择、待处理清单、处理进度、结果操作和必要错误信息。发票工具不展示通用
“可用次数”与“使用提示”侧栏，也不重复展示工具标题、隐私说明或排障阶段的技术文案。

页面仍从 `INVOICE_ZIP_MAX_MB` 读取单包选择上限，默认 20MB。历史服务端分析接口继续支持
`INVOICE_ZIP_BATCH_MB` 和 `INVOICE_ZIP_RESPONSE_MB`，但当前统一工作台不再调用该接口。

历史 `/tools/zip-extractor` 页面和分析接口由通用 `route_aliases` 机制映射到同一蓝图，
不会产生第二张首页卡片。历史分析接口保留供兼容和回滚使用；当前页面本地提取不调用用量
接口，因此不会因网关超时产生失败计量或重复计量。

## 生产、复用、成本与运维结论

- 生产影响：首页入口和工作台操作不变；ZIP 不再进入生产服务器，页面移除过时提示侧栏，
  发布无需迁移或停机。
- 复用：浏览器端递归、签名识别、内容摘要和安全预算保持独立函数；服务端内核保留为兼容
  边界。浏览器本地文件处理不适用于未来必须审计或持久化的 AI 任务，因此不提升为共享任务。
- 成本：提取、合并和导出全部在客户端完成，服务器不再承担 ZIP CPU、内存和响应流量。
- 新手部署：普通代码发布即可，JSZip 已作为静态资源随仓库发布；无新增 Python/Node 运行时
  依赖、数据库迁移、云资源或环境变量。
- 长期架构：本地无状态工具留在浏览器，服务端 AI、认证、存储和任务基础设施不被发票文件
  处理耦合，隐私和运维边界更清楚。

## 本地提取结果契约

`extractArchives` 按用户选择顺序合并并发任务的结果。每个顶层 ZIP 返回 `files`、`issues`
和 `error`：至少提取到一个 PDF 时把文件加入工作台并展示非致命问题；没有提取结果时保留
原 ZIP 及错误。该契约避免并发完成顺序改变文件顺序，也避免部分成功时丢弃整个压缩包结果。

## 验证与回滚

腾讯云主站 Flask 由宿主机 `mytoolbox.service` 运行，不属于
`deploy/docker-compose.production.yml` 的 AI Generation 容器。代码更新后必须执行
`sudo systemctl restart mytoolbox`，再用 `sudo systemctl status mytoolbox --no-pager`
确认服务为 `active (running)`。

发布后分别访问新旧网址，确认均显示统一工作台；同时上传两个分别可成功提取、其中至少一个
包含嵌套 ZIP 的真实样例；浏览器网络面板不应出现 `/tools/invoice-printer/analyze` POST，
工作台应得到两包内全部合规 PDF。再加入直接 PDF/图片，确认逐项删除、清空待处理、删除
勾选、清空全部、继续追加、批量打印和导出。再测试损坏、加密、超深和高压缩比 ZIP，确认
页面明确提示且文件仍保留。若需回滚，恢复上一版本代码并重启服务即可；没有数据库或持久
文件需要回退。
