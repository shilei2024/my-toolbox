# ADR-0037：客户优先导航、派生市场汇总与外部提醒调度

## Status

Accepted — 2026-09-06

## Why

业务需要在工作台看到所有授权跟进客户的 TAM、SAM、SOM，继续按品牌和类别分析；项目应从客户上下文进入；提醒必须在生产服务器上稳定执行真实邮件发送，而不只停留在可手工调用的 CLI。

## Decision

市场汇总复用现有项目物料口径，在请求时按项目权限范围对非归档项目派生，不新增数据库字段。主导航合并为“客户与项目”，新增客户详情作为项目入口；原项目 URL、全局台账和 API 保留兼容。邮件继续采用 PostgreSQL 发件箱与 SMTP 适配器，在腾讯云使用 systemd timer 每 10 分钟顺序调用配置自检、幂等扫描和发送命令。

## Alternatives Considered

- 预计算并持久化汇总表：读取更快，但会引入金额一致性、回填和迁移成本，当前规模没有必要。
- 删除全局项目路由强制客户入口：会破坏书签、导出和集成，因此只调整主界面入口。
- 在 Gunicorn 内运行定时线程：多 worker 会重复执行，发布重启还会漏跑，因此拒绝。
- 新增 Redis 队列或独立通知服务：当前 PostgreSQL 发件箱已满足幂等和重试，额外基础设施成本不成立。

## Future Impact

派生报表服务可继续增加负责人或客户分组；当数据规模使请求延迟超过目标后，可在保持输出契约不变的情况下改为 SQL 聚合或物化读模型。通知调度可被其他模块复用，但业务规则仍留在各自模块。

## Performance

工作台市场汇总使用项目、物料、竞品三次有界关系查询和线性内存聚合，避免逐项目 N+1。当前未新增缓存，以免展示过期商务金额。

## Cost

不新增数据库、Redis、容器或第三方 Python 依赖；systemd timer 复用现有腾讯云实例，唯一可变成本为邮件服务商发送量。

## Security

汇总严格复用项目范围权限。SMTP 凭据只由服务器环境文件注入；自检不输出秘密，测试邮件不包含客户数据；邮件链接要求生产 `APP_BASE_URL` 使用 HTTPS。

## Rollback Plan

停止并禁用 timer，关闭提醒扫描和真实发送开关即可立即阻止新邮件；应用可回退上一版本，无数据库降级。市场页和客户详情为只读派生界面，回退不影响业务数据。
