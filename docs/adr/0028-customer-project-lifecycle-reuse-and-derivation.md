# ADR 0028: 客户项目重新激活、衍生与快照报表边界

## Status

Accepted — 2026-08-28。适用于客户项目 Phase 3 生命周期首切片。

## Why

量产、失败、暂停和归档后的机会可能恢复，也可能形成产品二代或新的设计机会。直接覆盖旧项目会破坏复盘与审计；总是新建则切断来源关系。业务同时需要低成本汇总，但“当前阶段数量”不能伪装成历史转化率。

Golden Rule 结论：该功能会影响生产业务记录，必须受现有功能开关、RBAC、版本锁、幂等和 staging 门禁保护；阶段事件、权限与报表服务可供后续模块复用其模式；复用现有 PostgreSQL 字段和页面是最低运维成本方案；无迁移发布和明确回滚步骤便于初学者维护；边界符合模块化单体和数据库事实源架构。

## Decision

1. 重新激活保留同一项目 ID，只允许经理从暂停或终态进入进行中阶段，在同一事务更新负责人/跟进快照、成员主标记、版本、阶段事件和审计，不清除旧复盘字段。
2. 衍生项目生成新 ID、项目编号和独立阶段历史，写入 `derived_from_project_id`。客户默认沿用，成员、物料、竞品由用户选择复制；活动和旧阶段事件不复制。
3. 复制价格使用来源记录的汇率与双币快照，避免历史金额因外部汇率变化漂移。软删除资产不复制。
4. 生命周期报表按当前项目状态统计，沿用项目查询的数据权限。日期范围明确使用 `updated_at` UTC；响应携带生成时间、数据时点、范围、筛选和定义。
5. 本切片不新增标签模型、数据仓库、缓存、后台任务或数据库迁移。历史转化分析未来基于追加式阶段事件另建口径。

## Alternatives Considered

- 清空终态字段后直接恢复：界面更整洁但会丢失复盘事实，因此拒绝。
- 衍生时复制活动历史：阅读方便但会让一次活动属于两个生命周期，因此拒绝。
- 新建报表库或 Redis 缓存：当前规模收益不足且增加一致性与部署成本，因此拒绝。
- 把当前阶段数量称为漏斗转化率：无法表达历史流转，容易误导经营决策，因此拒绝。

## Future Impact

后续可增加标签复制、月/年业务日历、阶段事件转化分析和异步大报表；这些扩展不得改变已发布的项目来源关系和当前快照定义。若数据量使同步查询超过性能门槛，可增加按组织刷新的数据库汇总表，但 PostgreSQL 业务记录仍是事实源。

## Performance

报表先应用组织与项目可见范围，再限定三个终态；页面不做全域跨组织聚合。上线前需在真实 PostgreSQL 规模数据验证 P95，小规模首发不引入缓存。衍生复制在单个事务完成，UI/API 不提供无界批量衍生。

## Cost

复用现有 Flask、PostgreSQL、模型字段和部署单元，无新增云资源、依赖或常驻进程。成本只增加少量查询和复制记录的存储。

## Security

所有读取先验证组织和项目可见范围；重新激活需要组织管理员或业务经理；衍生需要写权限。跨组织对象返回 404。审计只记录稳定 ID、复制范围和安全状态，不记录联系人、复盘正文或价格详情。

## Rollback Plan

先关闭 `CUSTOMER_PROJECTS_ENABLED` 或收窄试点邮箱，再回退应用代码。本阶段没有 migration，不执行数据库 downgrade；已生成的项目、来源关系、阶段事件和审计继续保留。需要业务撤销时使用正常阶段/软删除流程，不直接删除生产记录。
