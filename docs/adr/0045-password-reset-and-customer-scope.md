# ADR-0045：忘记密码走管理员一次性码，报销客户按账号归属

日期：2026-10-31。状态：已接受，候选待生产验证。

## Why

1. 网站没有 SMTP，也没有任何重置流程；注册用户忘记密码只能找管理员手改数据库。
2. 报销工具共用组织客户目录，导致 A 录入的客户出现在 B 的选择列表里，与本工具“个人报销”的语义不符。

## 决定

**重置**：管理员在后台「用户」页为指定账号生成一次性码；用户到 `/auth/forgot` 填邮箱、码和新密码。码用 `itsdangerous` 以 SECRET_KEY 签名，载荷含 `uid` 与当前密码 hash 的摘要；成功改密后摘要变化，所有旧码自动失效（单次使用，无需新表/迁移/清理任务）。默认 TTL 60 分钟，可由 `PASSWORD_RESET_MODE`（admin/disabled）与 `PASSWORD_RESET_TTL_MINUTES` 配置。失败一律同一句提示，不泄露账号是否存在。

**客户**：报销模块的客户目录只返回“本人创建/本人负责”的客户；历史无创建者的行仍视为共享。组织、行数据与其它模块不变，网站与手机共用同一事实源。发票展示改用组织级解析，保证旧发票（引用他人客户）仍能显示名称与等级；新录入仍只接受本人目录中的客户。

## Alternatives Considered

- 邮件自助重置：需要 SMTP、发信域名、退信处理与防滥用，当前生产不具备；保留为未来模式（`PASSWORD_RESET_MODE` 可扩展）。
- 新增 reset token 表：需要迁移与清理任务，签名码已满足单次使用与过期。
- 客户改为新表/新迁移：成本高且会分散事实源，直接复用现有 owner 字段即可。

## Future Impact

- 邮件通道就绪时可增加 `email` 模式，接口与页面不变。
- 客户归属复用 `created_by_user_id/primary_owner_user_id`，未来组织内共享可加“共享给团队”开关，无需改表。

## Performance / Cost

每次重置一次签名/验签与一次密码 hash；无新服务、无新表、无额外存储。

## Security

码不落库、不进日志；后台只在生成时显示一次。重置换密后，手机 password 会话因其 subject 含密码摘要而立即失效；微信会话不受影响。客户隔离在服务端强制执行，伪造他人 customer_id 会被 400 拒绝。

## Rollback Plan

代码退回上一发布；重置码只是签名串，回退后自然失效；客户数据与发票未改动，无需回库。
