# ADR 0027: 客户项目跟进采用主站模块化单体与 PostgreSQL 事实源

## Status

Accepted — 2026-08-27. Phase 0 已由业务负责人确认，Phase 1 核心台账按本决策实现。

## Why

客户、项目、物料、竞品和跟进记录需要跨终端协作、组织隔离、乐观并发控制与完整审计。现有 Flask 主站已经提供登录、会话、CSRF、用户与统一后台；另建 CRM 服务会复制这些能力并增加部署、网络和维护成本。当前根目录模型依赖启动时 `create_all()`，不适合继续承载需要可演练、可回滚的生产迁移。

Golden Rule 结论：功能会影响生产，因此必须使用默认关闭的功能开关、只新增对象的兼容迁移与试点白名单；组织、角色、审计、通知发件箱和任务能力应设计为可复用平台能力；模块化单体是当前最低成本方案；正式迁移命令、检查与回滚文档保证初学者可维护；该边界保持统一后台和 PostgreSQL 业务事实源，符合长期架构。

## Decision

1. 在 Flask 主站新增独立 `customer_projects` 领域包。HTML/BFF 控制器保持薄层，权限、状态机、审计、查询和仓储分别放置；不得把模型继续堆入根 `models.py`。
2. V1 复用现有 `users`、Flask-Login、CSRF 与统一后台；组织、组织成员、审计事件与通知发件箱使用共享语义，首个消费者为客户项目域。
3. PostgreSQL 是生产唯一事实源。SQLite 只用于本地开发与单元测试，不承诺其并发锁行为等同生产。
4. 正式迁移使用 Alembic/Flask-Migrate 管理；禁止依赖 Web 进程启动时 `db.create_all()` 发布本模块。首批迁移仅新增表、索引和约束，不改变现有表字段。
5. 浏览器页面与 JSON API 同在 Flask 主站，API 前缀固定为 `/api/v1/customer-projects`。所有写操作服务端重验组织和项目权限。
6. 项目聚合根使用整数 `version` 做乐观锁；更新携带版本，版本不一致返回 409，绝不静默覆盖。
7. 阶段变化、活动快照、审计事件与通知意图在同一数据库事务写入。业务路由不直接发送邮件。
8. 提醒由外部调度器触发命令或签名内部端点；调度器不保存状态。V1 不新增 Redis、WebSocket、常驻 CRM 服务或 Web 进程内调度线程。
9. 发布受 `CUSTOMER_PROJECTS_ENABLED` 和试点成员范围双重控制。系统管理仍进入现有 `/admin`，不创建第二套后台。

## Frozen Phase 0 Defaults

- 首发一个组织，所有领域表从第一天包含 `organization_id`。
- 角色：组织管理员、业务经理、Sales、PM、FAE、只读/审计；一个用户可有多个角色。
- 阶段代码：`evaluation`、`initiated`、`sampling`、`pilot_batch`、`trial_production`、`design_win`、`mass_production`；辅助状态为 `paused`、`lost`、`archived`。
- 停滞阈值依次为 14、14、10、14、14、30 天；终态不触发，暂停按恢复日处理。
- 量产/失败由主业务发起，业务经理或组织管理员确认。
- 首发通知渠道为 SMTP 适配器；默认主业务必收，PM/FAE 由组织或项目策略抄送。
- 回收站保留 30 天；审计、阶段历史和通知至少保留 3 年。
- 历史 Excel 导入属于 Phase 4/V1.1，不阻塞核心台账首发。

## Alternatives Considered

1. 独立 CRM 微服务：隔离更强，但重复认证、权限、运维和观测，当前规模收益不足。
2. 放入 Generation Service：破坏 AI 生成领域边界并扩大生产故障面。
3. 继续使用 `create_all()`：本地简单，但无法审阅 SQL、演练升级或可靠记录生产版本。
4. WebSocket 实时协作：实时性更强，但 V1 的 15–30 秒版本检查和 409 冲突保护已满足需求。
5. Web 进程内 APScheduler：多 worker/Serverless 会重复或漏执行，不作为业务提醒触发器。

## Future Impact

组织、成员、审计和通知会先以清晰共享接口落地，未来 OCR、PDF、Writing 等模块可复用。只有出现独立团队、显著不同可用性目标或扫描任务持续超出一个周期时，才评估拆服务或增加队列；拆分时保留现有 API 和发件箱契约。

## Performance

所有列表先限定组织和可见范围，再使用游标分页；索引覆盖阶段、负责人/跟进时间、有效更新时间、项目编号和规范化型号。首发容量按单组织 100 活跃用户、10 万项目设计；在真实 PostgreSQL 上验证普通列表和详情 P95 小于 2 秒、写入 P95 小于 1.5 秒。

## Cost

复用 Flask、PostgreSQL 和现有服务器，不新增常驻服务、Redis 或长连接基础设施。新增成本仅包括数据库容量/备份、SMTP 发送量和外部定时触发；邮件设置组织每日上限以控制异常成本。

## Security

每次查询和写入都必须限定 `organization_id` 并执行服务端 RBAC；隐藏按钮不构成授权。沿用安全会话、CSRF、输入长度限制、同源策略和速率限制。审计差异对联系人和金额脱敏；公开错误只含稳定错误码、中文提示、字段错误和追踪 ID，不记录真实客户样例或供应商原始错误。

## Rollback Plan

应用回滚先关闭功能开关并回退应用版本；提醒回滚停止调度并把发送器切为 dry-run。首批迁移只新增对象，应用回滚时保留表、发件箱、审计和历史，不执行生产降级删除。只有在备份恢复演练、影响清单和发布审批完成后，才能另行清理无人引用的新表。
