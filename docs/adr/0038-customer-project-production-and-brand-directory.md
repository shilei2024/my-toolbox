# ADR 0038：量产状态简化与报销品牌目录选择

## Why

客户项目可能在系统启用前已经进入量产，因此新建项目需要支持直接记录量产状态。原有量产转换同时强制物料、日期和结果说明，阻碍了先登记事实、后补充细节的实际流程。推广物料品牌又与报销助手的产品线/品牌目录重复维护，容易产生拼写分叉；空的机会分类卡片也降低了项目详情页的信息密度。

## Decision

- `mass_production` 继续使用既有稳定状态码和状态目录，不新增数据库字段或迁移。业务经理、组织管理员可在新建项目时直接选择量产；服务端保留相同权限校验，防止通过 API 绕过页面限制。
- 转入量产只强制非空的阶段变更原因。实际量产日期和结果说明改为可选，提交时仍保存；阶段事件与审计记录继续保留原因。
- 推广物料表单读取当前登录用户在报销助手维护的 `ReimbursementProductLine` 名称列表，只呈现品牌名称。项目物料继续保存品牌名称快照，不建立跨用户外键，因为报销目录是用户所有、可重命名和删除，而项目属于组织共享数据。
- 无物料的机会分类不渲染卡片；完全没有推广物料时只显示添加入口。

## Alternatives Considered

- 为量产继续强制完整资料：数据更齐全，但不符合先记录业务事实的流程。
- 允许所有写权限成员直接创建量产项目：操作更快，但会绕过既有量产审批边界。
- 为物料直接增加报销产品线外键：看似关联更强，但用户所有权和组织项目所有权不一致，目录删除也会破坏历史引用。
- 新建组织品牌主数据表：长期可行，但当前需求只要求复用现有目录，会增加迁移和治理成本。

## Future Impact

若未来建立组织级统一品牌主数据，可将名称快照迁移为可选的共享品牌标识，同时继续保留快照用于历史审计。当前读取逻辑集中在页面适配层，不改变项目领域服务和 API 的字符串契约。

## Performance

项目详情增加一次按当前用户与排序索引查询品牌目录；返回数据量与报销助手目录一致。无目录时复用内置默认列表，不在 GET 请求中写数据库。

## Cost

无新增服务、依赖、数据库表或定时任务，运行成本不变。

## Security

只读取当前登录用户自己的报销目录，不跨用户或跨组织聚合；量产新建与转换均保留业务经理/组织管理员权限校验。页面显示名称，不暴露报销记录、品牌编号或所有权字段。

## Rollback Plan

回退应用提交即可恢复原表单和量产校验。没有数据库迁移；已经以量产状态创建的项目仍使用旧版本已支持的 `mass_production` 状态码，不会成为无效数据。
