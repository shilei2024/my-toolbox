# ADR 0033：客户项目留言/@ 与数量价格输入边界

状态：Accepted

## Why

业务需要在项目时间线内发表意见并明确提及协作者，同时要求单机数量和单价保持可计算、可读的一致精度。跟进活动会更新下一步、提醒时间和项目版本，不能承载纯协作留言。

## Decision

- 新增追加式 `project_comments` 与 `project_comment_mentions`；留言不修改项目快照或版本。
- 只能 @ 当前组织的有效成员，每条最多 10 人；首版只记录提及关系，不自动创建邮件或站内通知。
- 审计只记录留言 ID、正文长度和提及人数，不复制正文或邮箱。
- 单机数量新建/编辑时只接受非负整数，单位固定为 PCS；保留现有 Numeric 列兼容历史数据。
- 物料单价与竞品报价最多接受 5 位有效小数，折算价格按 5 位保存；页面与 API 去除末尾 0。
- 项目名称只作为现有基础信息表单的弹窗触发器，服务端仍执行权限、CSRF 和乐观锁。

## Alternatives Considered

- 复用项目活动：会误改下一步和提醒，拒绝。
- 把 @ 文本直接写入正文：无法验证组织边界、查询被提及人或未来复用通知，拒绝。
- 首版即发送邮件：会增加退订、重试和噪声治理成本；待真实通知需求确认后复用共享 outbox。
- 修改数量/价格列类型：会增加生产表重写与兼容风险，当前没有必要。

## Future Impact

提及关联可供未来统一站内通知或邮件适配器消费，但发送必须另立策略、幂等键和偏好设置。评论保持项目领域边界，不扩展为全平台聊天系统。

## Performance and Cost

每个详情页最多读取 100 条留言及其提及，使用项目时间索引和批量查询；不新增队列、缓存、对象存储或第三方服务。

## Security

评论沿用项目可见范围和写权限；被提及用户必须是同组织有效成员。正文按纯文本转义展示，最大 4000 字；跨组织 ID 返回业务校验错误，不写入数据。

## Rollback Plan

先关闭 `CUSTOMER_PROJECTS_ENABLED` 或回退应用。旧应用忽略新增表，生产保留评论与提及记录，不在事故中执行 downgrade。
