# ADR 0031: 客户项目个人与组织筛选视图边界

状态：Accepted — 2026-08-28。适用于客户项目 Phase 4 保存与组织共享视图。

## Why

业务用户需要复用常用项目筛选，组织管理员需要发布统一口径。这里的“共享”是组织内共享筛选配置，不是向互联网公开客户项目数据。

## Decision

- `project_saved_views` 使用组织 ID 和命名空间隔离：个人命名空间为 `user:{id}`，组织命名空间为固定 `organization`。
- 仅保存白名单字段 `q`、`stage`；应用视图后仍通过原项目查询和成员数据范围，不保存 SQL、任意表达式或外部 URL。
- 所有活跃成员可创建和删除自己的个人视图；只有 `organization_admin` 可发布或删除组织视图，同组织其他成员只读使用。
- 同一命名空间的规范化名称唯一，写入依赖数据库唯一约束；创建和删除均写共享审计。
- 删除的是筛选偏好而非业务事实，可物理删除；审计事件长期保留名称、范围、筛选和版本。

## Alternatives considered

- 公开 token 分享：会扩大客户和竞争情报的暴露面，当前需求没有授权匿名访问。
- 保存完整查询语句：难以长期兼容且产生注入和越权风险。
- 浏览器 localStorage：无法多端同步，也无法由管理员发布组织口径。

## Future impact, cost and performance

只新增一张小型配置表和有界列表查询，不新增缓存、队列或外部服务。未来增加客户、负责人等筛选时，只能通过版本化白名单扩展；旧视图应保持兼容。

## Security and rollback

视图 ID 不是授权凭据；每次读取仍校验登录、组织与命名空间。回滚时关闭模块并回退应用，生产保留新增表和审计，不执行 downgrade。
