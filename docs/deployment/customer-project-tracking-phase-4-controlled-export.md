# 客户项目 Phase 4 受控导出发布手册

## 生产影响与发布前检查

本阶段新增 `project_export_policies`，不修改现有业务数据。先备份 PostgreSQL，在 staging 从 `d5e6f7a8b9c0` 升级到 `e6f7a8b9c0d1`，确认唯一约束和三个范围检查约束存在。应用发布时保持 `CUSTOMER_PROJECTS_ENABLED=false`。

## 配置与验证

1. 在统一后台打开“客户项目设置”，确认默认允许角色仅为 `organization_admin`、`business_manager`，默认上限为 2,000 个项目和 20,000 行。
2. 使用经理试点账号筛选单个阶段并导出，确认文件只包含当前可见项目，不包含联系人电话或邮箱。
3. 关闭价格列后再次导出，确认六个价格/汇率列不存在；普通成员直接访问下载地址应为 403。
4. 用以 `=` 开头的项目名称验证单元格作为文本打开，不执行公式。
5. 在审计表确认 `customer_project_export/exported` 包含筛选、数量、策略版本与 64 位 SHA-256；超限请求产生 `blocked`。
6. 观察应用内存和响应时间后再扩大试点。不要为了绕过筛选而把同步上限提升到全库规模。

## 常见故障

- 页面没有导出按钮：检查组织策略允许角色和当前成员角色；不要只修改模板。
- 导出被重定向：当前结果超过项目或行数上限，缩小关键字/阶段筛选。
- 缺少价格列：策略必须启用价格列，且当前角色还需拥有价格编辑权限。
- 文件摘要不一致：确认核对的是原始下载文件；若仍不一致，保留审计和文件并停止扩大试点。

## 回滚

关闭 `CUSTOMER_PROJECTS_ENABLED` 并回退应用。生产保留 `project_export_policies` 和审计记录，不执行 Alembic downgrade。只需紧急禁用导出时，在统一后台清空允许角色并关闭价格列，不影响项目台账读写。
