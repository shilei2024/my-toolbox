# 客户项目跟进 Phase 1 迁移、发布与回滚计划

> 状态：Phase 1 基础模块已进入现网站发布流程；本次商务台账增强 migration `f1a2b3c4d5e6` 已实现并通过本地回归，生产执行前仍需完成 PostgreSQL staging、备份/回滚和审批。不要因基础页面可访问而跳过新 migration 门禁。

## 为什么这样发布

生产主站已在线，客户项目模块会新增含敏感业务数据的表和路由。发布采用“先只新增数据库对象、保持功能关闭、再对白名单开放”的顺序，使应用回滚不依赖破坏性数据库降级。

## 前置条件

- 独立 feature 分支通过代码评审、自动化测试和安全检查。
- staging 使用生产同版本 PostgreSQL，且不含真实客户、邮箱、竞品或金额。
- 已验证数据库全量备份能恢复到独立实例，并记录恢复时长。
- `CUSTOMER_PROJECTS_ENABLED=false`，试点成员为空；SMTP 使用 dry-run/测试收件域。
- 域名、DNS、TLS、Nginx/Cloudflare、Flask 进程、数据库、防火墙、容量、备份和监控按现有生产清单通过。

## Phase 1 迁移命令

使用 Flask-Migrate/Alembic；生产必须设置 `AUTO_CREATE_SCHEMA=false`，禁止由 Web 进程启动时建表：

```powershell
$env:FLASK_APP = "app:create_app"
flask db current
flask db upgrade
flask db current
```

预期结果：已安装基础模块的环境升级前显示 `8904db6a3fa5`；`upgrade` 只向 `customer_projects` 和 `project_materials` 增加可空列，不删除、不改类型、不回填历史数据；升级后输出 `f1a2b3c4d5e6`，进程退出码为 0。全新环境会依次创建基础表并应用新增列。任何 `DROP`、现有列类型改变或无界回填都必须阻断发布并重新评审。

迁移完成后初始化首发组织与管理员：

```powershell
$env:FLASK_APP = "app:create_app"
flask customer-projects bootstrap --admin-email "管理员邮箱" --name "业务组织名称"
```

预期输出包含不可逆组织 ID，不输出密码或业务数据。也可在现有统一后台“客户项目”页面完成同一初始化并分配成员角色。

## 预生产演练

1. 从脱敏备份恢复 staging 数据库，记录大小、开始/结束时间和校验摘要。
2. 运行 `flask db current`，确认基线与发布包一致。
3. 审阅待执行 SQL；确认仅新增对象、外键引用有效、索引可接受。
4. 执行升级并重复执行一次，第二次应无变更且成功。
5. 保持开关关闭启动旧/新应用，验证首页、登录、后台、现有工具和 Gallery 入口。
6. 仅对测试管理员开放，运行组织隔离、CRUD、409、软删除/恢复和审计用例。
7. 创建带产品名称/年用量的项目，设置客户评级；分别用 USD 和含税 CNY 录价，核对 13% 税率、汇率快照与 Excel 导出；确认 FAE 页面无价格输入且 API 写价返回 403。
8. 观察数据库连接、CPU、锁等待、错误率和延迟；完成备份恢复及应用回滚演练。

## 生产发布顺序

1. 获得发布审批并创建发布证据包；确认最新备份和恢复点。
2. 停止客户项目提醒触发器（Phase 1 默认不存在或保持 dry-run）。
3. 执行兼容迁移，功能开关保持关闭。
4. 部署应用并执行健康检查、登录和现有站点冒烟。
5. 开放内部管理员，再开放少量试点成员；至少观察一个完整业务日。
6. Phase 2 邮件上线前先完成 dry-run、幂等重放和测试收件域验证，再小流量启用。

## 成功验证

- 未授权用户看不到入口，手工构造 URL/API 仍为 404/403。
- 两个组织之间客户、项目、搜索、报表和审计均无法互读。
- 两个客户端以同一版本更新时，第二个返回 409 且首个内容不被覆盖。
- 新增有效跟进同时更新快照和审计；失败事务不留下部分记录。
- 关闭开关后所有客户项目入口不可用，现有主站功能保持正常。
- 旧项目仍可读取并显示“待补齐”；新项目必须填写产品名称和大于 0 的年用量。
- 价格记录保存原始币别、折算结果与汇率快照；FAE 无法通过页面或 API 修改价格。
- Excel 仅包含当前用户可见且符合筛选条件的数据，并产生 `customer_project_export` 审计事件。

## 常见失败与恢复

- **迁移失败：** 不反复在生产试错。保存脱敏错误与 revision，停止发布；若事务已回滚则修复新迁移并重新演练，若出现部分对象则按审核过的恢复步骤处理。
- **应用启动失败：** 保留新增表，回退上一稳定应用并保持开关关闭。
- **权限或跨组织测试失败：** 立即停止试点，关闭开关；不得用 UI 隐藏代替服务端修复。
- **查询变慢/锁等待：** 停止开放范围，记录查询计划；索引调整先在生产规模副本验证。
- **通知异常：** 停止触发器/发送器并切 dry-run，保留发件箱与发送记录，不删除失败任务。

## 回滚

首选回滚是关闭 `CUSTOMER_PROJECTS_ENABLED` 并部署上一稳定应用。`f1a2b3c4d5e6` 新增的可空列与价格快照全部保留，旧应用会忽略它们；不得在事故处理中执行 down migration。若数据库对象本身造成不可接受影响，必须在恢复演练、影响清单和单独审批后通过备份恢复/切换处理。
